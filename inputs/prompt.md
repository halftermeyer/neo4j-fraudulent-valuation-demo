## Data model — the customer's, keep it intact
Nodes: Incident, Instrument, Position, Desk, Person (with Role), ValuationMethodology, MethodologyChange, MarketPrice, PriceOverride, MAPReview, IPVReview, PnLSignal, Control, Policy, Approval, Committee, Escalation, RootCause, CorrectiveAction, Owner, Evidence.
Relationships: VALUED_BY, CHANGED_TO, OVERRIDDEN_BY, COMPARED_WITH, GENERATED_SIGNAL, SUBJECT_TO_CONTROL, APPROVED_BY, REVIEWED_BY, GOVERNED_BY, OWNED_BY, CHALLENGED_BY, ESCALATED_TO, EVIDENCED_BY, CAUSED_BY, MITIGATED_BY, IN_SCOPE_OF_READ_ACROSS.
Two design rules, both non-negotiable and to be settled before generating anything: every event node carries event-time (`at`, plus `validFrom`/`validTo` where relevant); risk attributes (issuer sector, maturity bucket, methodology family, liquidity tier, desk, approval-chain shape) are first-class `:RiskAttribute` nodes linked from Instrument/Position/Methodology, never properties — read-across matches attributes, not instrument fields. Add three demo-side node types only: `:ControlObligation` (what a Policy mandates), `:GovernanceGap` (a computed expected-vs-observed miss) and `:Pattern` (an abstracted case: `(:Pattern)-[:REQUIRES]->(:RiskAttribute|:GovernanceGap)`). Manage visual complexity by progressive reveal and community highlighting, not by dropping entities.

## Scenarios (the `Scenarios` tab, one function each, in this order)
- Explore: one position, its instrument, its price history vs proxy curve, then its signals added one at a time. Never open on the full graph.
- S1 Conjunction: "each signal is below threshold; connected, they have a shape" — one query aggregating PnLSignal, PriceOverride, MethodologyChange, missing IPVReview, skipped Approval around a Position; GDS community detection only if the community *is* the pattern; colour the community, grey the rest.
- S2 Chronology: event-time ordered reconstruction with QPP over the governance chain, and expected-vs-observed from `:ControlObligation` — "which control should have fired here and did not". One parameterised gap query for all rules. This scenario is also what the Assistant answers.
- S3 Abstraction: from the confirmed Incident, create and display the `:Pattern` node with its REQUIRES links (strip instrument identity, keep RiskAttributes + GovernanceGaps). The audience must see that the pattern is a template, not a lookup.
- S4 Read-across: match the `:Pattern` against every Position: exact matches ranked, partial matches with score = satisfied REQUIRES / total (the early-detection story), and predicted links via GDS link prediction/similarity ONLY with held-out ground truth (remove known links at generation time, show recovery, state it on screen). Clicking the false positive jumps back to S2 to show its controls did happen. The pattern must be widenable live (add/remove a REQUIRES) so the presenter can show that pattern size is not self-censored.
